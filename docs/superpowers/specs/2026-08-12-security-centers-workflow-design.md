# 任务、漏洞与报告中心工作流设计

## 目标

按素材稿重做任务中心、漏洞中心、报告中心的总览/列表/详情工作流，补齐服务端筛选、漏洞详情与处置、报告确认与导出记录，并让进行中和已完成任务都能回到原渗透执行会话回看历史。

## 边界

- 不改动 `/pentest` 与 `/pentest/session/:sessionId` 的现有视觉与核心执行交互。
- 允许新增必要的后端查询与状态接口，但不新增消息队列、权限体系或外部引擎能力。
- 所有页面展示真实 API 数据；接口暂时没有数据时展示素材一致的空态，不伪造业务结果。

## 页面设计

### 任务中心

任务列表采用素材中的六项指标卡、组合筛选栏、分页表格和行操作。筛选包含关键词、状态、类型、创建人、时间范围、团队；筛选参数写入 URL，服务端分页查询。任务名称/ID、摘要和详情均可进入 `/pentest/session/:taskId`；终态任务在执行页停止轮询但保留事件、子任务、漏洞和报告的最终快照，因此可回看。

### 漏洞中心

漏洞总览保留风险分布、趋势、来源分布、资产类型和业务 Top 5；所有图表共享范围筛选。漏洞列表增加等级、状态、来源模块、资产类型、所属业务、时间范围、AI 推荐和报告状态筛选，支持多选批量指派、批量改状态、加入报告、导出。行点击进入独立详情路由 `/vulnerabilities/:vulnerabilityId`，详情页展示基础信息、证据、AI 风险摘要、修复建议、复测状态和处置时间线；状态变更后刷新列表与详情。

### 报告中心

报告总览按素材稿展示六项指标、来源/等级分布、生成趋势、最新报告、最近导出和洞察。报告列表支持关键词、来源、格式、状态、时间范围筛选，保留预览和下载；新增确认、导出操作和导出记录查询。导出失败显示可重试错误态。

## 数据流与 API

- 列表接口接收筛选参数并返回分页结果，前端不在当前页之外做假过滤。
- 任务详情直接复用现有任务会话接口；任务中心只负责导航，不复制执行状态。
- 漏洞详情由列表基础字段加详情接口组成，所有处置操作携带漏洞 ID 和目标状态。
- 报告确认与导出记录通过报告接口完成，下载仍使用已鉴权 URL。

## 错误与空态

网络失败、权限不足、无结果和导出失败分别使用可重试错误条、权限提示、素材风格空态和行级错误提示。筛选变化重置页码并保留 URL 可分享。

## 验证

- 前端新增筛选、导航、详情和终态回看测试。
- 后端新增筛选参数、漏洞详情和报告操作测试。
- 运行前端 `build`、`lint`、`test`，后端 `ruff` 与相关 `pytest`。
