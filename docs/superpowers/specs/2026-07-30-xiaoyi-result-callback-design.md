# 小易结果回传接口设计

## 目标

在不改变现有小易任务创建协议的前提下，按《数字人对接文档》完善平台已有的资产、漏洞、日志和报告接收接口，使小易可以使用自己的数值计划 ID 和任务 ID 回传结果，并让结果准确进入当前平台任务。

## 已确认问题

- 平台已有 `/api/ai/upload-asset`、`upload-vulnerability`、`upload-log`、`upload-report`。
- 现有请求模型要求平台 UUID；小易持有的是 `xiaoyi_plan_mappings.id` 和 `tasks.external_task_id`。
- 接口支持 Bearer JWT，但缺少针对外部 ID 的统一解析。
- 相同回调重试会重复写入。
- AI 日志只进入 `ai_logs`，当前任务页主要读取 `task_events`，因此客户看不到关键回传。

## 方案

保留数字人文档的四个路径和 JWT 鉴权。每个请求允许 `plan_id` 为平台 UUID 或小易数值计划 ID，允许 `task_id` 为平台 UUID 或小易任务 ID。后端通过已有映射表解析为平台组织、计划和任务，绝不信任请求自行声明的组织归属。

新增 `ai_callback_receipts` 记录回调类型、规范化请求摘要和资源 ID。同一完整请求重试时返回首次创建的资源 ID，不重复写入业务表。

所有回传原文继续执行现有脱敏和 URL 安全检查。日志完整保存在 `ai_logs`；warning、error、阶段完成、报告完成等关键日志同步生成 `task_events`，由现有任务页轮询展示。普通调试日志不进入专家咨询区。

## 接口兼容

- 保留现有平台 UUID 调用方式，避免破坏已有数字人客户端。
- 数值 `plan_id` 映射 `xiaoyi_plan_mappings.id`。
- 字符串 `task_id` 映射 `tasks.external_task_id`，且必须属于解析后的计划。
- 响应继续使用平台统一 `success/message/data`，同时在 `data` 中返回文档所需的 `plan_id`、`org_id` 和结果 ID。
- 不向 `/api/osCore/chat` 添加小易文档未确认的回调字段；回调地址和数字人账号由小易侧配置。

## 安全与边界

- 仅 `is_digital_human=true` 或管理员账号的有效 JWT 可调用。
- 组织由 JWT 和计划映射共同确定；跨组织请求返回 403。
- 未知计划返回 404，任务与计划不匹配返回 422。
- 报告 URL 禁止内嵌凭据；正文沿用 5 MB 上限。
- 不引入 Redis、消息队列、微服务或第三方依赖。

## 验收

1. 使用数字人账号登录获取 JWT。
2. 以小易数值计划 ID 和外部任务 ID 分别回传资产、漏洞、日志、报告。
3. 四类结果正确关联平台任务。
4. 相同请求重复发送只产生一条业务数据。
5. 错误日志和新漏洞在任务页三秒轮询窗口内出现。
6. 非法 JWT、跨组织、未知映射和任务错配被明确拒绝。
