# 平台结果归集与本地报告设计

## 目标

小易继续负责扫描与渗透执行。平台负责保存其可用结果、提取已确认漏洞、保留失败原因，并在上游没有提供报告时生成可预览和下载的本地 Markdown 报告。

## 边界

- 不修改小易接口、请求格式或部署。
- 不增加微服务、队列、数据库表或第三方依赖。
- 不把工具输出原样交给大模型，也不根据不完整证据编造漏洞。
- 上游 `reportUrl` 和数字人报告回调继续有效；平台报告仅作为本地兜底。

## 数据流

1. 同步器获取父任务、子任务和子任务工具结果。
2. 工具结果先脱敏，再将有限摘要保存到子任务 `raw_external`。
3. 解析工具结果内明确存在的 `vuln_info`；按任务、标题和资产键幂等写入现有 `Vulnerability`。
4. 终态时聚合父任务、子任务、漏洞和工具摘要，使用确定性模板生成 Markdown，写入现有报告目录并创建 `Report`。
5. 有有效执行证据但上游最终状态失败时，平台标记为 `PARTIAL_SUCCEEDED`；没有有效证据时保留 `FAILED`。
6. 父任务和子任务均保存上游错误或工具失败摘要，前端可直接展示。

## 安全与容量

- 本地报告只包含结构化摘要、漏洞证据节选和修复建议。
- 单个工具结果摘要限制长度，凭证字段继续使用现有脱敏函数。
- 报告文件名由平台任务 UUID 生成，不使用外部路径。
- 重复同步不会重复创建漏洞或报告。

## 验收标准

- 失败工具使用顶层 `errorMessage` 时，任务仍能显示原因。
- 返回有效 `vuln_info` 时，平台漏洞列表出现对应记录。
- 没有 `reportUrl` 时，终态任务仍产生本地 Markdown 报告。
- 有漏洞或成功工具证据且部分步骤失败时，状态为 `PARTIAL_SUCCEEDED`。
- 原有回调、外部报告、预览和下载接口保持兼容。
