# 桌面浏览器响应式适配设计

## 目标

在不改变现有页面架构、业务流程、视觉素材和依赖的前提下，使平台在常见桌面浏览器宽度及 125%/150% 缩放下保持可读、可操作且无横向裁切。

本次重点覆盖 1280–1920px 桌面视口。手机和平板端不在范围内。

## 已确认约束

- 右侧“专家咨询区”在窄桌面和高缩放场景下继续固定显示在主内容右侧，不移动到底部，也不改为抽屉。
- 保留侧栏导航、主内容区、专家咨询区和现有设计素材。
- 不新增依赖，不修改后端接口、数据结构或业务流程。
- 优先使用现有 CSS 与 Ant Design 响应式能力，避免引入窗口监听状态。

## 根因

全局样式对 `html`、`body` 和 `#root` 设置了 `min-width: 1180px`。浏览器可用 CSS 视口小于该值时，页面不会继续收缩，而是产生横向溢出。与此同时，渗透测试页固定使用 352px 专家区、260px 侧栏和较大的主视觉比例，使 1280px 或高缩放场景下的主操作区过窄。

## 方案

采用纯 CSS 分档压缩方案，不增加运行时布局状态。

### 宽屏：1600px 及以上

- 保持现有 260px 侧栏和 352px 专家咨询区。
- 保持现有主视觉、页边距和标题尺寸。

### 中等桌面：1440–1599px

- 专家咨询区收紧至约 320px。
- 缩小全局搜索框、页面横向间距和卡片间距。
- 主视觉按可用空间缩放，确保输入表单优先获得宽度。

### 窄桌面与高缩放：1280–1439px

- 专家咨询区保持约 280–300px，并继续位于右侧。
- 收紧侧栏占用、页头间距和非关键操作间距。
- 隐藏装饰性人物背景与轨道图形，主输入区扩展到剩余空间。
- 长 URL、标签和对话内容允许安全换行，不撑开网格列。

## 弹窗适配

- 授权扫描弹窗的目标宽度仍为 720px，但最大宽度受视口安全边距限制。
- 步骤条在空间不足时允许标题紧凑显示，避免超出弹窗。
- 资产标签、长 URL、警告文本和底部操作按钮允许换行。
- 弹窗内容过高时由内容区域滚动，关闭按钮和关键操作保持可访问。

## 其他页面

移除全局固定最小宽度后，为已有仪表盘、列表和执行工作台补充桌面级收缩保护：

- 多列指标和卡片网格在窄桌面减少列数或间距。
- 表格继续使用其自身的横向滚动，不扩张整个页面。
- 页头搜索和用户信息优先压缩非关键空间，避免互相覆盖。
- 登录页保持居中，卡片宽度不得超过视口安全边距。

## 测试与验收

- 增加自动化断言，确保不再存在全局 `1180px` 最小宽度，并确认关键响应式规则存在。
- 运行前端单元测试、类型检查、生产构建和代码检查。
- 在 1280、1440、1920px 宽度检查主要页面。
- 在 125% 和 150% 浏览器缩放下检查：
  - 页面无整体横向滚动；
  - 侧栏、主操作区和专家咨询区均可见；
  - “开始分析”和后续预检按钮可点击；
  - 授权弹窗完整显示，长 URL 不导致溢出；
  - 专家消息和输入框保持可读、可用。

## 非目标

- 不实现手机或平板专用导航。
- 不将专家咨询区改为抽屉或底部区域。
- 不重做页面视觉风格，不替换现有素材。
- 不修改扫描、CDN/WAF 检测、小易或 DeepSeek 的业务逻辑。
