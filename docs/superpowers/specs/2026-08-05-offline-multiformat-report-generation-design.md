# 离线三格式渗透测试报告设计

## 目标

平台以用户提供的《渗透测试报告.md》章节结构为准，将一次任务的同一份数据快照生成 Markdown、DOCX 和 PDF 三种报告。生成过程在 API 单体服务内完成，运行时不访问外部转换服务，不新增微服务。

## 约束

- Markdown 是唯一内容源，DOCX 和 PDF 不维护独立正文模板。
- DOCX 由 Pandoc 和随镜像发布的 `reference.docx` 生成。
- PDF 由同一 DOCX 经 LibreOffice 无界面模式转换，减少三种格式的内容与版式偏差。
- 任务回传不能因 DOCX/PDF 转换失败而失败；已成功的格式保留并可下载，失败原因写入任务事件。
- 转换命令使用参数数组执行，不经 shell；设置超时、独立临时目录与独立 LibreOffice 用户目录。
- 报告正文中的口令、令牌、Authorization、Cookie 等敏感值在渲染前统一脱敏。
- 不加载远程图片或远程样式，模板、字体和转换程序均包含在镜像中。

## 内容结构

静态章节沿用参考文档：服务结果、渗透范围、渗透结果、安全建议、服务概述、测试人员、测试目的、测试流程、测试工具、测试标准、漏洞描述、风险评级和漏洞评级。

动态数据来自当前任务、子任务、小易工具回传和平台已确认漏洞。每个漏洞包括名称、风险等级、影响资产、描述、验证证据和修复建议；缺失字段明确显示“未提供”，不推断未回传的事实。

## 生成与存储

1. 在任务进入终态且已有工具执行证据后读取一次数据快照。
2. 渲染并原子写入 Markdown。
3. 以 Markdown 生成 DOCX。
4. 以 DOCX 生成 PDF。
5. 每个成功文件各创建一条现有 `reports` 记录，使用同一 `task_id` 关联；重复同步只补齐缺失格式。
6. 每种格式独立发布 `report_available` 事件；转换失败发布 `report_generation_failed`，包含格式和可读错误。

无需数据库迁移。现有组织隔离、报告下载和审计逻辑继续复用。

## 前端呈现

报告中心按任务聚合，同一任务只显示一行，并给出 Markdown、DOCX、PDF 三个格式入口。Markdown 保留在线预览；DOCX/PDF 直接下载。部分格式未生成时显示不可用状态，不隐藏失败事实。

## 容器与运维

API 镜像安装 Pandoc、LibreOffice Writer、Noto CJK 字体和 Poppler 工具。报告目录继续使用现有持久卷。健康检查不依赖转换程序启动进程，但构建和部署验证会检查二进制版本并实际生成、渲染一份样例报告。

## 验收标准

- 同一任务可下载内容一致的 `.md`、`.docx`、`.pdf`。
- 报告结构与参考 Markdown 对齐，中文字体与分页可读。
- 报告中不出现样例文档的真实 IP、令牌或与当前任务无关的证据。
- 重复同步不产生同格式重复记录。
- DOCX/PDF 单项转换失败时 Markdown 仍可用，错误可在任务事件中追踪。
- 容器断网时仍能完成三格式生成。
