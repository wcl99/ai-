# 小易子任务失败信息可见性设计

## 背景

平台父任务能够正常创建小易任务并轮询状态，但真实响应中的子任务使用
`childTaskId`、`currentPhase` 和 `errorMessage` 字段。现有适配器只识别
`taskId`/`id`、`phase`，导致失败子任务未写入平台数据库，页面只能显示父任务
`FAILED`，无法解释失败原因。

## 目标

- 兼容小易文档及真实响应中的子任务字段。
- 在平台任务详情中显示子任务状态和小易提供的失败原因。
- 保留现有任务、同步器和页面架构，不增加依赖或自动重试策略。

## 方案

在现有 `EngineTask` 归一化边界完成兼容：识别 `childTaskId`、
`currentPhase` 和 `errorMessage`，并将错误信息保存到平台子任务。同步父任务时仍按
现有流程拉取子任务；若小易顶层没有错误信息，平台不伪造原因，而由子任务列表
展示小易的原始业务错误。

任务详情页面复用现有子任务数据，在时间线中展示失败子任务的名称、状态、阶段、
目标和错误信息。敏感字段继续经过现有脱敏逻辑，页面不展示令牌或完整原始响应。

## 错误处理

- 小易提供 `errorMessage` 时原样保存为经过长度限制的业务错误。
- 小易未提供错误时保持为空，不猜测原因。
- 子任务接口临时不可用时沿用现有跳过并记录服务日志的行为，不把父任务误判为失败。
- 不自动重启或重试已经失败的扫描，避免重复扫描和模型费用。

## 验证

- 单元测试用本次真实响应字段验证子任务 ID、阶段和错误映射。
- 同步测试验证失败子任务能够落库并由 `/children` 返回。
- 前端测试验证失败原因可见且无错误原因时安全降级。
- 运行 API、Web 单元测试、构建和目标页面回归测试。
