# 漏洞与报告总览统计设计

## 目标

补齐漏洞总览和报告总览中当前显示为空状态的统计区域，并保证万级数据量下查询快速、数据准确。实现沿用 FastAPI、SQLAlchemy、React Query 和现有 CSS，不新增微服务、缓存、统计表或前端图表依赖。

## 功能范围

### 漏洞总览

- 风险概况：展示严重、高危、中危、低危和未知漏洞数量。
- 漏洞趋势：支持 `当日`、`3日`、`7日`、`历史`四个时间范围。
- 来源分布：按漏洞 `data_json.source_tool` 聚合；缺失来源归为“小易回传”。
- 修复建议：根据严重/高危、待修复、待复测数量生成确定性提示，不调用模型生成不可验证结论。
- 现有指标卡、最近漏洞和修复进度继续使用真实数据。

### 报告总览

- 报告来源：`external_url` 非空归为“小易回传”，否则归为“平台生成”。
- 生成趋势：支持 `当日`、`3日`、`7日`、`历史`四个时间范围。
- 报告等级：按 `report_level` 聚合，展示标准报告、部分结果和其他。
- 报告洞察：展示总数、近期新增、部分结果数量和最新报告时间。
- 最近报告列表保持现有交互。

## 时间范围与颗粒度

- `today`：客户时区当天 00:00 至当前时刻，按小时聚合；包含当前小时，不返回尚未发生的未来小时。
- `3d`：过去 72 小时，按小时聚合，最多 72 个点。
- `7d`：包含今天在内的最近 7 个自然日，按日聚合，固定 7 个点。
- `all`：从组织内最早记录到当前时间；不足 90 天按日，否则按月聚合。
- 所有区间使用左闭右开边界 `[start, end)`，避免边界记录重复。
- 数据库存储和筛选使用 UTC；分桶使用浏览器提供的 IANA 时区，无效时区回退 `Asia/Shanghai`。
- 没有记录的时间桶由服务端补零。历史聚合只改变展示颗粒度，不抽样、不漏计。

## API

新增两个组织隔离的只读接口：

- `GET /api/v1/vulnerabilities/overview?range=today|3d|7d|all&timezone=Asia/Shanghai`
- `GET /api/v1/reports/overview?range=today|3d|7d|all&timezone=Asia/Shanghai`

每个接口一次返回指标、分布、趋势、颗粒度和洞察所需数据。列表接口保持兼容。

## 数据与性能

- 聚合在数据库内完成，不通过分页列表统计，也不把完整记录加载到 Python。
- 新增联合索引：
  - `vulnerabilities(org_id, created_at)`
  - `reports(org_id, created_at)`
- PostgreSQL 使用时区转换和 `date_trunc` 聚合；SQLite 测试使用等价的 `strftime` 表达式。
- 单组织 1 万条漏洞和 1 万份报告时：数据库聚合 P95 不高于 100ms，完整 API P95 不高于 300ms，前端切换范围后 500ms 内更新。
- 暂不增加缓存；只有实测无法达到指标时才评估短缓存或汇总表。

## 前端呈现

- 时间选择器放在趋势卡片标题右侧，仅影响趋势卡片。
- 趋势使用现有轻量 SVG/CSS 折线或柱状表达。
- 来源和等级使用现有 `rank-bars`/进度条样式。
- 加载时显示骨架或加载提示；接口失败显示错误和重试；数据为空时显示零值图表，不再显示“接口未提供”。
- 统计数值、图例和时间标签均来自接口，不生成推测数据。

## 测试与验收

- API：组织隔离、当日/3日/7日/历史、当日零点与当前小时、时区边界、左闭右开、空桶补零、来源回退、等级回退。
- 前端：范围切换请求参数、图表数据、空数据、错误重试，以及不再出现旧占位文案。
- 性能：在 PostgreSQL 中生成万级测试数据，确认查询使用联合索引，并记录 P95。
- 回归：运行完整 API 测试、前端测试、lint、类型检查和生产构建。

## 非目标

- 不改动漏洞和报告明细业务流程。
- 不增加第三方图表库。
- 不引入物化视图、统计微服务、消息队列或定时聚合任务。
