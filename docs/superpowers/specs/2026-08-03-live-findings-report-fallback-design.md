# 实时漏洞与报告兜底设计

## 目标

在渗透任务执行页面实时呈现小易工具结果中已确认的结构化漏洞，并在小易报告打包因 `ZIP entry size is too large or invalid` 失败时，由平台已有的本地 Markdown 报告能力接管最终报告，不把仅报告打包失败误呈现为整项渗透失败。

## 范围与约束

- 保留现有 FastAPI 单体、React 前端、TanStack Query 和小易适配器。
- 不修改小易服务，不新增依赖、消息队列或微服务。
- 只接收明确的 `vuln_info` 结构，不从自然语言推断漏洞。
- 继续使用现有任务、漏洞、报告、事件和审计模型，不新增数据库表或迁移。
- 其他扫描、渗透、网络或工具失败保持原状态，不被报告兜底逻辑掩盖。

## 数据流

1. 后端同步运行中子任务时，同时读取该子任务的工具结果。
2. 复用现有 `extract_vulnerabilities` 和持久化去重规则，将新漏洞增量写入当前父任务。
3. 前端任务页继续每三秒按 `task_id` 查询漏洞；新记录进入后显示在执行监测卡片的“实时漏洞”区域。
4. 任务结束时，如果小易没有提供可用报告，平台继续生成本地 Markdown 报告。
5. 如果唯一剩余异常是已知 ZIP 报告打包错误，且本地报告已经成功生成，则父任务改为成功、清除面向客户的失败提示，并写入一条“平台报告已接管”的任务事件，保留可审计事实。

## 界面

“实时漏洞”位于执行监测卡片内、进度与指标之后、错误提示之前。区域显示漏洞总数，并按发现时间倒序展示：风险等级、漏洞名称、影响资产和发现时间。描述放在折叠详情内，避免大量文本挤占任务主视图。无漏洞时显示“等待小易回传已确认漏洞”。

## ZIP 错误处理

只识别明确的 `ZIP entry size is too large or invalid` 报告打包错误。满足以下全部条件才接管：

- 已存在有效工具执行证据；
- 平台本地报告生成成功并持久化；
- 收集到的任务错误全部属于该已知报告打包错误。

接管后父任务为 `SUCCEEDED`，本地报告为 `READY`；任务事件记录小易报告打包失败以及平台报告接管。子任务的原始小易状态和原始响应仍保留，便于技术排查。

## 验证

- 后端测试证明运行中的子任务也会持久化漏洞，重复同步不会产生重复记录。
- 后端测试证明仅已知 ZIP 报告错误且本地报告成功时，父任务转为成功；其他错误仍保持部分成功或失败。
- 前端测试证明实时漏洞位于执行监测卡片内，显示数量、等级、名称、资产和时间，详情默认折叠。
- 前后端全量测试、静态检查和生产构建通过。
